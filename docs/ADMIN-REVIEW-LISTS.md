### 2.1 「字符串顺序 vs 数值顺序」备忘

- 字符串逐字符比：`100.1.1.1` < `193.122…` < `45.139…` < `9.1.1.1`（`1` < `4` < `9`，所以 45 夹在中间）——人看着像乱序；
- 数值四段比：`9.1.1.1` < `45.139…` < `100.1.1.1` < `193.122…`——符合 IP 段直觉；
- 两者都能把**同一 IP 聚在一起**，差别只在相邻 IP 的先后；本批统一用数值序。

## 3. AQ · 列表排序

### 3.1 异常审核（客户端排序）

- 表头可点：**最近出现**（`last_seen`）、**IP**（`ip`）、**次数**（`hits`）、**规则**（`rule`）；
- 默认「最近出现 ↓」；点击循环：升 → 降 → 回默认；
- 切换排序**不重置筛选**（只看待审/全部）；
- IP 比较函数 `compareIp(a,b)`（`frontend/src/utils/ipSort.js` 新建）：
  - IPv4 → `a*2^24 + b*2^16 + c*2^8 + d` 比较；
  - IPv6 / 异常值 → 排在所有 IPv4 之后，内部按字符串比较；
  - 空值最后；
- 排序状态存 `localStorage['admin.reviewSort']`（`{prop, order}`），刷新后保留。

### 3.2 访问明细（服务端排序）

`GET /api/admin/visitors` 增加 `sort` / `order`：

| sort | 含义 | SQL |
|---|---|---|
| `time`（默认） | 最近出现 | `id desc/asc` |
| `ip` | IP 数值序 | 零填充键：`case when ip ~ '^\d{1,3}(\.\d{1,3}){3}$' then lpad(split_part(ip,'.',1),3,'0')||'.'||… end asc/desc nulls last, id desc` |
| `status` | 是否被拦截 | `blocked asc/desc, id desc` |

- `order` 只接受 `asc` / `desc`，其它值回落默认；**参数白名单**，不拼接用户输入；
- 换排序时前端 `visitorPage=1` 重新拉取；
- 排序状态存 `localStorage['admin.visitorSort']`；
- **不用 `ip::inet` 强转**：脏数据（空串/非 IP）会让整条查询报错；零填充字符串排序等价且安全，IPv6/异常值排最后。

### 3.3 待审上限 500

- `pg.js` 的 `listAbuseReviews` 上限 `Math.min(..., 500)`；`/api/admin/reviews` 默认 `limit=500`；
- 前端不传 limit（走默认）；
- 列表头部显示「共 N 条（上限 500）」，超过 500 时提示"待审过多，先按 IP 合并处理"（AR）或按状态筛选。

### 3.4 AQ 验收

1. 两个列表表头可点，默认「最近出现 ↓」；点 IP 后顺序为 `9.x → 45.x → 100.x → 193.x`；
2. 同一 IP 多行在 IP 排序下**连续**；IPv6/异常值排在 IPv4 之后；
3. 换排序时访问明细回到第 1 页；筛选条件不丢；
4. 刷新页面后排序状态保留（localStorage）；
5. 非法 `sort`/`order` 参数回落默认，不报 500；
6. 10 万行量级下访问明细排序响应与现在同量级（人工抽查 `EXPLAIN`，必要时补 `(blocked, ip)` 索引——本批先不加）；
7. `npm test` 全绿（新增 `test/ip-sort.test.js` 与接口参数用例，并入主链）、`npm run frontend:build`、`npm run scan`。

## 4. AR · 按 IP 合并（下一期）

### 4.1 视图

待审列表**默认且唯一**展示合并视图（2026-11-10 修订：不再提供开关，见 §4.5）：

```
IP              规则摘要                        总次数  首次→最近           设备  状态    操作
45.139.104.172  secret-file ×2 · vcs-dir ×1      4    11-09 03:12→10:20   1    待审    封IP 封设备 忽略
```

- 分组键 = `ip`；组内规则按 `hits` 降序；
- 汇总：`rules`（去重计数）、`hitsTotal`（求和）、`firstSeen`（min created_at）、`lastSeen`（max last_seen）、
  `devices`（去重 fingerprint/device_id 数）、状态：
  - 有 `pending` → `待审`；
  - 全部 `auto_banned` → `已封禁`；
  - 混合 → `部分已处理`（展开看每条）；
- 展开行：每条规则一行（规则 / 次数 / 最后路径 / 最近时间 / 状态 / 设备指纹）；
- 勾选合并行 = 选中该 IP 的全部**待审**记录；批量栏显示「已选 N 个 IP · M 条记录」。

### 4.2 处置语义

| 动作 | 作用范围 |
|---|---|
| 封 IP | 该 IP 全部 pending 记录 → 复用 `reviews/approve-ip`（id 列表；>50 时分批） |
| 封设备 | 该 IP 全部 pending 记录对应的**全部指纹** → `reviews/approve-device`（去重后分批） |
| 忽略 | 该 IP 全部 pending 记录 → `reviews/reject` |

确认弹窗必须写明：「将处理 `45.139.104.172` 的 **3 条规则 / 4 次命中 / 1 个设备**」，高危动作沿用批量操作的二次确认。

### 4.3 排序

合并视图同样支持表头排序：最近出现（默认）/ IP / 总次数 / 规则数；复用 §3.1 的 `compareIp()`。

### 4.4 AR 验收

1. 进入「异常审核」即按 IP 合并：同一 IP 的多条规则合并成一行，规则摘要/总次数/首末时间/设备数正确；
2. 展开能看到每条规则的次数、路径、时间、状态、指纹；
3. 状态混合显示「部分已处理」；只看待审时只统计 pending；
4. 封 IP / 封设备 / 忽略的作用范围是该 IP 全部待审记录，确认弹窗条数与实际一致；
5. 勾选合并行后批量栏显示 IP 数与记录数，执行后列表刷新；
6. 页面上**没有**「按 IP 合并」开关，也不再渲染明细表；源码/构建产物里不应出现 `admin.reviewMerge`（测试断言）；
7. 移动端卡片化展示（每张卡 = 一个 IP，展开看规则）；
8. `npm test` 全绿、`npm run frontend:build`、`npm run scan`。

### 4.6 2026-11-10 修订（AZ）：规则摘要列精简

**问题（2026-11-10 所有者）**：合并视图「规则摘要」列把该 IP 的**全部规则**逐条拼出
（如 `cms-probe ×1 · script-ext ×1 · secret-file ×1 · vcs-dir ×1`），一个 IP 带 3–4 条规则就占满整行，
列表元素过多、可读性差。

**决策（所有者 2026-11-10，选「首规则 ×n · 共 N 条规则」）**：

1. 列内只显示**首规则**（该 IP 命中次数最多的规则，`row.rules` 已按次数降序）与**规则总数**：
   `secret-file ×2 · 共 3 条规则`（列宽固定，不再随规则数变长）；
2. 悬停该单元格 → 弹层（el-popover）列出**全部规则** `规则 ×n`（每行一条，按次数降序）；
3. 明细仍以展开行为准（`merged-detail-row`：每条规则的规则/命中/路径/时间/状态），不重复渲染；
4. 移动端卡片同口径：`首规则 ×n · 共 N 条规则`，详情走展开（卡片内已有展开/点击查看明细）。

**改动清单**

- `AdminModules.vue` 合并表 `ruleCount` 列模板：`{{ row.rules[0]?.rule }} ×{{ row.rules[0]?.n }} · 共 {{ row.ruleCount }} 条规则`，
  外层 `el-popover`（content 内 `v-for` 全部规则）；
- 合并移动卡片：`{{ row.rules[0]?.rule }} ×{{ row.rules[0]?.n }} · 共 {{ row.ruleCount }} 条规则`（替换现在 `row.rules.map(...).join(' · ')`）；
- 样式：`main.css` 的 `.merged-detail-row` 不变；新增弹层内小样式（复用 Element Plus 默认即可）。

**验收**

1. 合并视图「规则摘要」列固定宽度、单行不溢出；显示 `首规则 ×n · 共 N 条规则`；
2. 悬停单元格弹层列出该 IP 的全部规则（含每条次数），与展开行明细一致；
3. 只有 1 条规则的 IP 显示 `规则 ×n · 共 1 条规则`（不出现空弹层或重复）；
4. 移动端卡片同口径、展开明细正常；
5. `npm test` 全绿（`test/admin-review-lists.test.js` 断言改为「首规则 + 共 N 条规则 + popover」）、
   `npm run frontend:build`、`npm run scan`。
