# 后台功能对齐排查：旧控制台 → Vue 后台（缺什么 + 恢复规格）

> 状态：**已排查，待开发**（2026-11-03 17:00）。适用 v1.12.1。
> 排查方法：① 后端 `/api/admin/*` 路由（40 个）与前端实际调用（36 个）做差集；
> ② 旧零构建控制台 `web/console.html` 的页面/功能区逐项对照 Vue 后台（Console.vue + AdminModules.vue + AdminExtras.vue）。

## 1. 排查结论

### 1.1 缺失的功能（后端有接口/数据，前端没有入口）

| # | 功能 | 后端接口 | 旧控制台 | 现状 |
|---|---|---|---|---|
| 1 | **设备指纹列表** | `GET /api/admin/devices` | 「设备指纹」页 | ❌ 无入口 |
| 2 | **设备封禁管理** | `GET /api/admin/device-bans`、`POST /api/admin/devices/ban`、`DELETE /api/admin/device-bans/:fingerprint` | 「设备封禁」表（封禁/解封） | ❌ 无入口（审核弹窗可"封设备"，但封了看不见、解不了） |
| 3 | **合并重复游戏** | `POST /api/admin/games/merge` | 「高级维护：合并重复游戏」 | ❌ 无入口 |
| 4 | **同步运行历史** | `GET /api/admin/sync/runs` | 「同步结果」列表 | ❌ 无入口（运行日志页只显示文本日志） |
| 5 | **回填实时进度** | `GET /api/admin/backfill/status` | 进度展示 | ⚠️ 任务页只显示"运行中"，无进度 |

### 1.2 后端存在但新旧前端都没用的接口（冗余，可保留/后续清理）

- `GET /api/admin/heat/status`
- `GET /api/admin/rename/status`

> 任务状态统一走 `/api/admin/sync/status`，这两个接口目前是死代码；恢复进度展示时可以复用或删除。

### 1.3 已确认已迁移的功能（逐项核对过）

访问明细/统计、异常审核、IP 黑名单/白名单、自动封禁记录、回收站、编辑游戏、同步与回填
（价格/目录/回填/改名/热度）、站点通知、用户管理、Steam 账号、邮件服务（SMTP/测试/发送记录）、
系统设置、数据统计（价格变化/封面缓存/备份/浏览排行/高频 IP）、运行日志、版本检测。

## 2. 恢复规格

### 2.1 设备 tab（方案 B，本次确认）

**位置**：后台「访问与安全 → 访问记录」下新增第 4 个 tab「设备」：
`visitorTabs = [访问明细, 异常审核, 封禁与白名单, 设备]`。

**页面结构（AdminModules.vue `visitorView==='devices'`）**：

1. 「最近设备」表格（`GET /api/admin/devices?limit=100`）
   - 列：最近出现、IP、设备 ID、指纹（前 12 位，悬停全量）、UA（截断）、操作
   - 操作：「封禁」→ 弹窗选时长（10 分钟 / 1 小时 / 1 天 / 永久）→ `POST /api/admin/devices/ban`
     `{ fingerprint, minutes }`（永久传 `minutes: 0` 或 null，按后端现有语义）
2. 「已封设备」表格（`GET /api/admin/device-bans`）
   - 列：指纹（前 12 位）、设备 ID、封禁至（`until` 为空=永久）、备注、操作
   - 操作：「解封」→ `DELETE /api/admin/device-bans/:fingerprint`（二次确认）
3. 顶部说明：「设备封禁按指纹生效，换 IP 也会命中；白名单 IP 不受影响」。

**注意**：`device_bans.until` 为空表示永久；解封后该设备仍会出现在「最近设备」里（历史记录不删）。

**验收**：

1. 最近设备列表显示真实访问过的设备（含指纹/UA/IP）；
2. 对某设备点「封禁 10 分钟」→ 该设备刷新页面进入封禁页；「已封设备」出现记录；
3. 解封后设备恢复访问，「已封设备」记录消失；
4. 审核弹窗「封设备」产生的封禁，也能在「已封设备」里看到并解封；
5. 手机端 tab 可切换、表格可横向滚动。

### 2.2 合并重复游戏

**位置**：后台「游戏管理 → 游戏目录」工具栏加「高级」按钮 → 弹窗「合并重复游戏」。

- 表单：源 AppID（被合并方）、目标 AppID（保留方）→ 确认；
- 调 `POST /api/admin/games/merge`（`{ fromAppid, toAppid }`），返回合并的报价/快照行数；
- 成功后刷新列表；失败展示后端错误（如目标不存在、同 ID）；
- 弹窗内注明：「用于同一游戏被收录两次（不同 AppID）时人工合并；报价与历史会迁到目标游戏」。

**验收**：构造两个重复条目 → 合并 → 源条目消失、报价/历史归到目标、列表刷新正确。

### 2.3 同步运行历史

**位置**：「运行日志」页顶部加一块「同步记录」表（`GET /api/admin/sync/runs?limit=20`）。

- 列：开始时间、模式（steam-prices/catalog/backfill/rename/heat/…）、状态、请求数、总量、成功/跳过/失败、备注、耗时；
- 支持刷新；失败行红色标记；
- 与下方实时日志配合：先看"跑了什么"，再看"输出"。

**验收**：跑一次价格刷新后，同步记录出现一行（模式/状态/条数/耗时正确）。

### 2.4 回填/任务实时进度（可选，建议做）

- 在任务卡「运行中」时轮询 `GET /api/admin/backfill/status`（rename/heat 同理），显示：
  `已完成 X / 总 Y（Z%）· 速度 N 款/分钟 · 预计剩余 M 分钟`；
- 进度接口若返回结构不一致，先统一（或只在"运行中"显示已有字段）。

**验收**：运行增量回填时，任务卡显示进度百分比并随时间推进。
