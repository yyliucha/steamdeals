## 3. 服务端（CI-1）

- 新增 `src/alerts-html.js`：纯函数 `renderAlertsHtml(hits, { now, siteUrl })` → `{ subject, html, text }`；
  - 品牌头（SteamDeals + 日期）、每条提醒一张卡片、页脚「价格以商店结算页为准」；
  - 复用 price-report-html 的写法：内联 CSS + table 布局、无外部资源、**所有动态字段 HTML 转义**；
  - 卡片字段沿用 `toPayload()` 口径：名称、当前价、目标价（有才显示）、史低（有才显示）、原因角标、Steam 链接。
- `src/cli.js` 提醒路径：`deliver({ text, html, payload, subject })`（文本兜底保留）。
- `src/alerts.js` 保留 `renderDigest()` 作为纯文本兜底与 webhook 内容，不改其口径。
- 不新增接口；`deliver()` 契约不变。

## 4. 前端 / 后台（CI-2）

改 `frontend/src/components/AppealsAdmin.vue`：

1. **分段控件**：筛选行改用分段控件样式（`el-radio-group` 的 button 形态或新增 `.seg-tabs`——沿用现有主题 token，选中主色填充、显示「待处理（N）」计数）；
2. **空态**：桌面表格补统一卡片式空态（与移动端 `el-empty` 同口径），不再显示默认「暂无数据」；
3. **表格列**：按效果图收敛为 编号 / 提交时间 / IP / 联系方式 / 封禁原因 / 状态 / 操作；
   「到期」不单独成列，改为「封禁原因」单元格副行小字（`reason · 到期 时间`）；
4. **间距**：模块卡片与表格间距、页脚空白收紧；
5. 移动端卡片逻辑不变；不新增搜索/导出。

- 本批不涉及列表/队列/审核决定继承（只改样式与邮件渲染）。

## 8. 安全

- 前端：无新增用户输入；分段控件/空态不涉及权限逻辑。
