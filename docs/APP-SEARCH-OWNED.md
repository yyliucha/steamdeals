# App 搜索/列表口径修复：已拥有被排除 + 数据量受限（CV，P0 体验）

> 状态：**已确认待开发（2026-11-18，线上实测定位）**。
> 关联：[TODO.md](TODO.md) CV 条目、[APP-PARITY.md](APP-PARITY.md)（App 与 Web 对齐）、
> [SEARCH-I18N.md](SEARCH-I18N.md)（搜索口径）。

## 1. 现象与根因（2026-11-18 实测）

**现象**：安卓 App 搜索「赛博朋克2077」→ 「暂无数据」；Web 能搜到。App 还感觉"数据很少"。

**实测**：
- 用 App 完全相同的参数 + UA 请求服务端：`/api/app/games?region=cn&q=赛博朋克2077&page=1&pageSize=50&type=all` → **`total=1`（赛博朋克 2077）**，服务端搜索正常；
- **根因**：App 搜索请求**未带 `owned` 参数** → 服务端默认 `owned='exclude'`（`src/store/pg.js:1553`）→
  **登录用户的已拥有游戏被整批排除**；该游戏在你的 Steam 库里 → 搜索为空。Web 当时是**未登录**（游客不做 owned 过滤）→ 能搜到。
- **"数据少"同源**：已拥有整批排除 + App 每页 50 条 + 前端本地筛选（CM 前的已知限制①）。

## 2. 修复方案

| # | 内容 |
|---|---|
| 1 | **搜索不排除已拥有**：App 搜索请求带 `owned=include`；结果卡片标「已拥有」（复用 `owned` 字段）。浏览列表保持 `exclude`（与 Web 一致）。 |
| 2 | **Web 搜索同口径**（一致性）：Web 搜索框提交时同样用 `owned=include`，列表页签仍 `exclude`；两端口径一致。 |
| 3 | **数据量**：App 列表/搜索保持分页 50 + 滚动加载；若仍偏少，评估把"已拥有"作为可切换筛选（默认包含，可一键排除）。 |
| 4 | **验收凭据**：App 搜索「赛博朋克2077」返回 1 条且标「已拥有」；未登录/未拥有时不标；Web 同场景一致。 |

## 3. 验收

1. 登录且拥有该游戏：App 搜索 → 出现「赛博朋克 2077」并标「已拥有」；Web 搜索同结果；
2. 未登录：两端口径一致（能搜到，无"已拥有"标记）；
3. 浏览「全部」列表仍排除已拥有（不变）；
4. App 搜索结果分页/加载更多正常；
5. `npm test`（搜索 owned 参数断言）/ `frontend:build` / `scan` 全绿；App 侧 JVM 单测补"搜索带 owned=include"。
