## 1. 现状与代码事实（2026-11-12 核对）

**一句话：系统已经是「服务端有状态会话」，但会话只有「固定到期」，没有列表、没有踢人、没有空闲超时、过期行也不清理。**

而且过期行不删、后台计数不过滤，进一步像"永不失效"。本批要做的不是"加一个清理任务就好"，而是把**语义**补齐。

## 3. 设计

### 3.1 数据模型（`sessions` 加列，BK-2 完成）

```sql
-- 老库增量迁移（src/store/pg.js 的 migrate()，全部幂等）
alter table sessions add column if not exists id bigint generated by default as identity;
alter table sessions add column if not exists ip text;            -- 建会话时的客户端 IP（原样，供展示）
alter table sessions add column if not exists ip_key text;        -- 归一化键（IPv4 /24、IPv6 /64），只用于比较
alter table sessions add column if not exists user_agent text;    -- 原样 UA（列表展示用摘要）
alter table sessions add column if not exists ua_key text;        -- 归一化键（浏览器家族+主版本）
alter table sessions add column if not exists device_id text;     -- 现有设备 cookie 里的设备码
alter table sessions add column if not exists last_seen_at timestamptz;  -- 最近活动（5 分钟节流写）
update sessions set last_seen_at = created_at where last_seen_at is null;
create unique index if not exists ux_sessions_id on sessions (id);
create index if not exists idx_sessions_user on sessions (user_id);
create index if not exists idx_sessions_expires on sessions (expires_at);
```

要点：

- **`token` 仍是主键**，`id` 只是对外标识——**接口一律用 `id`，绝不把 `token` 下发前端**（token 是凭据）；
- **老会话没有 `ip_key` / `ua_key` / `last_seen_at`**：绑定校验只对"两个 key 都非空"的新会话生效，老会话只做过期判定，
  避免上线瞬间把所有人踢下线；`last_seen_at` 回填 `created_at` 以便空闲超时立刻可用；
- 表是"每会话一行"的小表，加列与索引成本可忽略。

### 3.2 会话解析收敛（BK-2 建骨架，BK-3 挂校验）

现在同一请求最多查 3 次 `userBySession`（`server.js:466/725/772`）。收敛为一次：

```
resolveSession(q, token, req)  // 每请求最多一次，结果缓存到局部变量
  ├─ 查 sessions join users（含 id/username/role/disabled/must_change_password/ip_key/ua_key/last_seen_at/expires_at）
  ├─ 已过期（expires_at <= now()）→ 视为未登录（**不在这里删行**：删除交给 `prune`，避免过期判定变成每请求写库）
  ├─ BK-3：空闲超时（idleDays > 0 且 now - last_seen_at > idleDays）→ 删行 + 401 + session.idle_expired
  ├─ BK-3：绑定校验（ip_key / ua_key 与当前请求不一致）→ 删行 + 401 + session.bound_mismatch
  └─ 通过：节流写 last_seen_at（同一会话 5 分钟内最多一次），返回用户
```

- 失效时对浏览器**顺手清 cookie**（`Set-Cookie: gp_session=; Max-Age=0`），避免反复带死 token；
- 公开接口/静态资源不受影响：解析失败按"未登录"处理（与现在过期会话的表现一致），只有 `requireUser` / `requireAdmin` 才返回 401/403；
- 绑定比较口径（**本规格的实现建议，见 §7 待确认**）：
  - IPv4 比较**前 24 位**（`1.2.3.x` 视为同一出口，运营商 NAT/同网段切换不误伤）；
  - IPv6 比较**前 64 位前缀**（展开 `::` 后取前 4 组）；
  - UA 比较**浏览器家族 + 主版本**（`Chrome/130`、`Safari/17`、`Edge/130`、`Firefox/131`、`MicroMessenger/8`…），
    忽略小版本、平台串与 `Windows NT 10.0` 这类细节；
  - 完全字符串相等会让"移动网络切网 / Chrome 自动升级"变成频繁掉线，故不采用（若所有者坚持，改比较函数即可）。

### 3.3 后台会话列表与踢下线（BK-2）

**接口**（全部 `requireAdmin`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/sessions?user=&ip=&includeExpired=&limit=&offset=` | 默认只列未过期；按 `last_seen_at desc nulls last, created_at desc`；`limit` 1–200、`offset` ≥0 |
| DELETE | `/api/admin/sessions/:id` | 踢单条（按 `id`，不是 token） |
| DELETE | `/api/admin/users/:username/sessions` | 踢该用户全部；**目标是当前管理员自己时保留当前会话** |
| POST | `/api/admin/bulk`，`target:'sessions', action:'kick'` | 批量踢，`keyType:'id'`、`max:200`、`risk:'low'`（走既有 `BULK_ACTIONS` 派发与 `admin_bulk_ops` 审计） |

**返回字段**（每行，绝不包含 token）：

```
{ id, username, role, ip, region, userAgent, deviceId,
  createdAt, lastSeenAt, expiresAt, current, disabled }
```

- `region`：用 `visitors.cachedRegion(ip)`，未命中返回 null（**不**在这一页触发外部归属地查询）；
- `current`：服务端用当前请求 token 与该行 token 比较得出（仅返回布尔）；
- `disabled`：账号是否被禁用（列表里能看出"僵尸会话"）。

**前端**（`frontend/src/pages/Console.vue` + `AdminModules.vue`）：

- 菜单：`账号与服务` 组新增 `{ id: 'sessions', label: '登录会话', glyph: '⟳', description: '查看在线会话、踢下线' }`；
- 列表列：用户（角色 tag）/ IP + 归属地 / 设备（`deviceId` 摘要 + UA 摘要，tooltip 全文）/ 登录时间 / 最近活动 / 到期时间 / 当前会话标记 / 操作（踢下线）；
- 筛选：用户名、IP、`包含已失效`（默认关）；分页 20（复用 `useListPagination`）；
- 批量：复选框 + `BulkBar`（动作「踢下线」，二次确认写明"目标用户下一次请求即退出登录"）；
- 移动端：卡片式（同现有各表的移动卡片样式），至少保留用户/IP/最近活动/踢下线；
- 空态：「当前没有在线会话」。

### 3.4 前台「退出所有设备」（BK-3）

- 接口：`POST /api/user/sessions/revoke-others`（需登录）→ 删除该用户除当前 token 外的全部会话，返回 `{ removed }`；
- 入口：`frontend/src/pages/ChangePasswordPage.vue`（唯一的账号安全页）加一张「登录设备」卡片：
  按钮「退出其它所有设备」+ 说明「保留当前设备；其它设备需要重新登录」；成功提示「已退出 N 台设备」；
- **不新增前台设备列表页**（决策 3）；当前设备要一起退就用现有「退出登录」；
- 审计：`session.revoke_others`。

### 3.5 清理（并入 `prune`，不新建任务）

- `src/store/pg.js` 的 `purgeOldRows` 增加 `sessions` 计数：
  - BK-1：`delete from sessions where expires_at < now()`；
  - BK-3 扩展：`or (last_seen_at is not null and last_seen_at < now() - make_interval(days => $idle))`（空闲超时的兜底清理，
    `idle=0`（关闭）时跳过该分支）；
- `cmdPrune`（`src/cli.js:2044`）输出追加「登录会话 N 条」，日志 `maintenance.cleanup` 带 `sessions`；
- 合并评估（`gameprice-requirements` §4.1）：无外部请求、与访问记录同属本地运维清理、`prune` 已并过 `steam_account_logs` 先例
  → **并入，不新建定时任务**；`sessions` 是每会话一行的小表，单轮顺序扫描可忽略；每周跑一次足够（过期行最多多留 7 天）。

### 3.6 B 组正确性修复（BK-1）

1. **单条禁用立即踢**：`PATCH /api/admin/users/:username` 里 `disabled` 从 false→true 时，
   删该用户全部会话（复用 `db.deleteSessionsOfUsers`），日志 `user.disabled_sessions_revoked { username, removed, by }`；
2. **兜底过滤**：`userBySession` 增加 `and not u.disabled` —— 即使会话行残留，被禁用用户的请求一律视为未登录（401）；
3. **会话计数只算未过期**：`listUsers` 的子查询加 `and s.expires_at > now()`（前端「登录会话 N 个」不再虚高）；
4. **过期行清理**：见 §3.5。

> 三条互不依赖，可单独发；但按 `BK-1 → BK-2 → BK-3` 顺序做，避免同一张表反复改迁移。

### 3.7 设置项（BK-3）

在 `src/settings.js` 的 `auth` 组追加（保存后经 `hydrateSettings` 写回 `process.env`，热加载约 15 秒）：

| key | env | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| `auth.sessionIdleDays` | `AUTH_SESSION_IDLE_DAYS` | int（0–90） | **7** | 空闲多少天失效；`0` = 关闭空闲超时 |
| `auth.sessionBindIp` | `AUTH_SESSION_BIND_IP` | bool | **true** | IP 变化是否失效 |
| `auth.sessionBindUa` | `AUTH_SESSION_BIND_UA` | bool | **true** | UA 变化是否失效 |

- 设置页自动按现有 schema 渲染，无需改前端；
- 绑定校验读取 `process.env`（与现有 `AUTH_REGISTRATION_ENABLED` 同一模式），**不新增每请求 DB 查询**；
- 关掉开关后立即不再拦截（已有会话保留，下次请求起生效）。

## 4. 验收

### BK-1（B：正确性修复 + 过期清理）

1. 管理员**单条禁用**用户后：该用户全部会话行被删除（`count=0`），旧 cookie 请求 `/api/me` → `user=null`；
   任何受保护接口 → 401；日志有 `user.disabled_sessions_revoked`。
2. 即使手工插一条该用户的会话（模拟残留），受保护接口仍 401（`userBySession` 过滤 `disabled`）。
3. 批量禁用行为不变（仍立即踢，且回执 `ok` 数正确）。
4. 用户列表「登录会话」只统计未过期：构造 1 条过期 + 1 条有效 → 显示 1；删除过期行后不变。
5. `node src/cli.js prune` 删除全部过期会话行，输出含「登录会话 N 条」，日志 `maintenance.cleanup` 带 `sessions`；
   未过期会话与其它表数据不受影响；连跑两次第二次删 0 行（幂等）。

### BK-2（A：会话列表 + 踢下线）

6. 后台「账号与服务 → 登录会话」出现菜单与列表；列字段齐全；默认只显示未过期；分页 20、按最近活动倒序；
   筛选用户名 / IP 生效；「包含已失效」能列出过期行。
7. 同一账号两处登录（两个 cookie）→ 列表两行；`current` 只在当前请求的那一行是 true；**接口响应中不出现 token**。
8. 踢单条：`DELETE /api/admin/sessions/:id` → 该行删除、目标浏览器下一次请求 401 并跳 `/login`；
   当前会话不受影响；日志 `session.kicked`。
9. 批量踢：勾选 3 条 → `bulk` 回执 `ok=3`、`skipped=0`；`admin_bulk_ops` 有对应记录（含操作者）。
10. 按用户踢全部：`DELETE /api/admin/users/:username/sessions` → 该用户会话清空；
    目标是自己时**保留当前会话**（列表里其它自己的会话被删）。
11. 权限：`/api/admin/sessions` 未登录 401、非管理员 403；批量越权（非管理员调用）403，且不改库。
12. `last_seen_at` 写节流：同一会话 5 分钟内连续请求 10 次，`last_seen_at` 最多更新 1 次（可观测：两次请求之间值不变）。

### BK-3（C：空闲超时 + 绑定 + 前台退出）

13. 空闲超时：把某会话 `last_seen_at` 改成 8 天前 → 下一次请求 401、会话行被删、日志 `session.idle_expired`；
    6 天前 → 仍可用（7 天阈值）；`auth.sessionIdleDays` 改 0 → 不再拦截。
14. IP 绑定：会话建在 `203.0.113.9`（`ip_key=203.0.113.0/24`），用 `203.0.113.77` 请求（同 /24）→ 仍可用；
    用 `198.51.100.7` 请求 → 401、会话删除、日志 `session.bound_mismatch field=ip`。
15. UA 绑定：`Chrome/130.0.1` → `Chrome/130.0.2` 仍可用；换成 `Firefox/131.0` 请求 → 401、日志 `bound_mismatch field=ua`；
    设置 `auth.sessionBindUa=0` 后不再拦截。
16. 老会话（无 `ip_key`/`ua_key`，迁移前创建）不会被绑定校验踢掉（只按过期/空闲判定）。
17. 前台「退出其它所有设备」：两处登录 → 点按钮 → 另一处下一次请求 401，当前设备仍可用；提示数量正确；
    日志 `session.revoke_others`；点击前有二次确认。

### 8.1 现象与证据（2026-11-13 11:13，生产 v2.11.0）

**现象**：所有者离开一段时间后回到后台页（`/console?section=games`），再操作时浏览器整页跳到
`https://sd.yyliucha.cn/login?next=%2Fconsole%3Fsection%3Dgames`，页面只有纯文本 **`not found`**。

| # | 结论 | 证据 |
|---|---|---|
| 1 | **`/login` 没有登记进 SPA 回退白名单**：白名单只有 `/`、`/console`、`/setup`、`/banned`、`/appeal` 及其 `.html` 变体 | `src/server.js:3750` |
| 2 | 未命中的路径落到旧 `web/` 目录找文件，找不到就返回**纯文本 404 `not found`** | `src/server.js:3726`（`serveStatic`） |
| 3 | 全仓 `src/` 里**没有任何** `'/login'` 字符串——服务端从未登记过这个页面 | `grep -n "'/login'" src/*.js` 无结果 |
| 4 | `/login`、`/register`、`/change-password` 是 AL 批（v2.1.0，2026-11-09）新增的前端路由，白名单没跟着更新 | `frontend/src/router/index.js:21-23`；`git log -S "change-password" -- src/server.js` 无提交 |
| 5 | 后台页的 401 处理是**整页跳转**（`window.location.href='/login?next=...'`），不是 Vue 路由 | `AdminModules.vue:329`、`AdminExtras.vue:116`、`AdminLogs.vue:211`、`AnnouncementDrawer.vue:95`、`UserCreateDrawer.vue:76` |
| 6 | 前台首页的 401 是**软跳**（`router.push`），且 `/api/me`、`/api/login` 明确不跳 → 所以登录页平时"能用"，只有硬跳才 404 | `Home.vue:200` |
| 7 | 没有全局 401 拦截器，也没有鉴权路由守卫（router 只有标题与未保存提醒） | `frontend/src/router/index.js:27-29` |
| 8 | 会话失效的三个来源：空闲超时 / IP·UA 绑定 / 自然到期；前两个有日志，第三个无 | `src/server.js:484`（`session.idle_expired`）、`:496`/`:502`（`session.bound_mismatch`） |
| 9 | 空闲超时的存量口径有坑：迁移把老会话的 `last_seen_at` 回填成 `created_at` → **登录超过 7 天的老会话，在 v2.11.0 部署后第一次请求就被判空闲过期** | `src/store/pg.js:450-452`、`src/server.js:477-487` |

| # | 决策 |
|---|---|
| 1 | **BM-1（P0）**：SPA 回退白名单补齐 `/login`、`/register`、`/change-password`，并加测试防止以后新增页面再漏 |
| 2 | **BM-2（P1）**：迁移口径改为「老会话 `last_seen_at = now()`」，不再用 `created_at`——**今后部署不会再把老会话一次性判空闲过期**；生产已发生的那次不回滚 |
| 3 | **BM-3**：**做**——6 处 401 跳转收敛成一个 `redirectToLogin(reason)` 软跳（`router.push`，带 `next` 与 `reason`），登录页提示「登录已过期，请重新登录」；用户感官比整页跳好，也不会再撞白名单 |

### 8.4 设计

**8.4.1 BM-1 白名单（必做）**

`src/server.js` 的 `serveFrontendStatic` 白名单追加三个路径（与现有 `.html` 变体写法一致）：

```js
'/login', '/register', '/change-password',
```

**测试**：新增断言——`GET /login`、`/login?next=%2Fconsole`、`/register`、`/change-password` 都返回 **200** 且
`content-type: text/html`（index.html）；并把"前端 router 里的页面路径"与"服务端白名单"做一致性断言
（新增页面忘记登记时测试直接红，避免再犯）。

**8.4.2 BM-2 迁移口径（必做）**

`src/store/pg.js` 的迁移：

```sql
-- 老会话：空闲计时从"部署这一刻"开始，而不是从创建时间开始（否则登录超过 7 天的会话会立刻被判空闲）
update sessions set last_seen_at = now() where last_seen_at is null;
```

- 已执行过旧迁移的库不会命中该语句（列已非空），所以对生产**不会**产生二次影响；
- 不延长 `expires_at`（绝对上限仍 7/30 天），只是把"空闲 7 天"的起点修正为"部署/首次活动时刻"。

**8.4.3 BM-3 统一 401 软跳（做）**

- 新增 `frontend/src/utils/session.js`：`redirectToLogin(reason = 'expired')`
  - 已经在 `/login` 就直接返回（防循环跳）；
  - 先调 `bypassNextGuard()`（`frontend/src/composables/useUnsavedGuard.js:96`，否则"未保存的修改"提醒会把跳转拦下来）；
  - 再 `router.push({ path: '/login', query: { next: 当前 fullPath, reason } })`——**软跳，不再整页导航**；
- 5 处后台硬跳全部改用它：`AdminModules.vue:329`、`AdminExtras.vue:116`、`AdminLogs.vue:211`、
  `AnnouncementDrawer.vue:95`、`UserCreateDrawer.vue:76`；
- 前台 `Home.vue:200` 的软跳补 `reason`（其余不变；`/api/me`、`/api/login` 仍不跳）；
- `LoginPage` 读 `route.query.reason === 'expired'` → 表单上方提示「登录已过期，请重新登录」；登录成功后按 `next` 回跳（已有逻辑）。

**8.4.4 BM-4 会话心跳（做）**

新增 `frontend/src/composables/useSessionHeartbeat.js`，在 `main.js` 挂**一次**（单例，避免每页各起一个定时器）：

- 触发：每 **5 分钟** 一次 + `visibilitychange` 回到前台时补一次（页面隐藏时跳过定时探测，省请求）；
- 探测：`GET /api/me`（`credentials: 'same-origin'`、`cache: 'no-store'`），只看 `user` 字段；
- **基线判定**：只有"上一次探测是已登录、这一次变成未登录（`user === null` 或 401）"才跳转——
  游客、从未登录的访客不会被误跳；主动"退出登录"由现有逻辑处理，不会触发心跳跳转；
- 网络错误 / 5xx / 429：本轮跳过，**不跳转**（避免离线时把人踢走）；
- 公开页不探测也不跳：`/login`、`/register`、`/setup`、`/banned`、`/appeal`；
- 命中失效 → 调 BM-3 的 `redirectToLogin('expired')`；
- 心跳**不改会话策略**：不续期、不刷新 `expires_at`，只负责"发现失效"。

### 8.5 验收

1. `GET /login`、`/login?next=%2Fconsole%3Fsection%3Dgames`、`/register`、`/change-password` → **200 + index.html**，浏览器直接打开/刷新不再 `not found`。
2. 白名单一致性测试：前端 router 里每个页面路径都在服务端白名单里（未来新增页面漏登记 → 测试红）。
3. 会话失效（删 `sessions` 行模拟）后，在后台任意页触发一次请求 → 跳到登录页且**页面正常渲染**；登录成功后回到 `next`。
4. 后台 5 处 401 跳转行为一致（软跳、带 `reason`、不被未保存提醒卡住）；前台首页行为不变（`/api/me` 仍不跳）；
   源码里 `window.location.href = '/login` 归零（测试断言）。
5. 登录页显示「登录已过期，请重新登录」（`reason=expired` 时）；不带 `reason` 直接打开登录页不显示该提示。
6. **心跳**：登录态页面在服务端删掉会话后，≤5 分钟（或切回前台时立即）自动软跳登录页并带 `reason=expired`；
   游客（从未登录）停留任意久都不被跳；离线/5xx/429 时心跳只跳过、不跳转；`/login` 等公开页不发探测请求；
   全局只起一个定时器（切页不叠加）。
7. 迁移幂等：连跑两次无副作用；新库无影响；老库第一次启动执行一次。
8. `npm test` / `npm run frontend:build` / `npm run scan` 全绿（新增 `test/serve.test.js` 页面路由断言与
   `test/session-heartbeat.test.js` 前端静态断言，接入 `npm test` 主链）。
9. 部署侧复核：直接打开 `https://<站点>/login` 返回登录页；控制台会话失效后回到登录页而不是 `not found`；
   挂着控制台不动 5 分钟后（或切回标签页）自动回登录页并提示「登录已过期」。

### 8.6 本批不做

1. 不改会话策略本身（空闲 7 天、IP/UA 绑定、记住我 7/30 天都不动）；
2. 不改封禁页/黑白名单/申诉流程；
