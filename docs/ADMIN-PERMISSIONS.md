## 0. 总原则

- 权限两级：`admin`（全量）/ `user`（普通用户，5 个页面）；不做权限树。
- 三保险：前端菜单隐藏 + 路由守卫 + 后端接口 403（`/api/admin/*` 已有 requireAdmin）。
- 普通用户只能看自己的数据：页面走用户级接口，接口忽略请求里的 `userId`/`username`。

## DT-1 菜单与路由权限隔离

- **菜单**：admin 全量（内容运营 / 访问与安全 / 账号与服务 / 日志审计 / 系统）；
  普通用户仅 5 项：**个人资料 / 登录会话（我的设备）/ 我的到价提醒 / 我的愿望单 / 站点公告（只读）**。
- **删除「Steam 账号」菜单项**（管理员也不需要）：账号管理并入个人资料页（CX 账号卡）；
  管理员的账号查看需求在「用户管理 → 编辑用户」弹窗里只读显示该用户绑定的 Steam 账号。
- **路由守卫**：访问无权限 `section`（`/console?section=users` 等）→ 重定向到 `profile` + 提示「无权限」。
- 验收：普通用户 Console 只见 5 项且直达 URL 被守卫跳回；admin 全量；删除「Steam 账号」菜单后无残留入口。

## DT-2 用户级数据接口 + 5 页数据接入

- 新增接口：
  - `GET /api/me/sessions`：只返回当前用户会话（设备/IP 归属地/UA 摘要/最近活动/到期/当前会话）；
  - `POST /api/me/sessions/:id/revoke`：只能踢自己的会话（非自己的 404）；
  - `GET /api/me/wishlist`：自己的愿望单（分页/搜索），复用 wishlist 服务层。
- 前端：普通用户的 5 个页面全部改用用户级接口——
  会话页 → `/api/me/sessions*`；到价提醒 → `/api/watchlist`；愿望单 → `/api/me/wishlist`；公告 → `/api/announcements`；
  个人资料不变。管理员页面保持 admin 接口不变。
- 防御：以上接口强制 `session.user.id`，忽略任何传入 userId；越权返回 403/404 并审计。
- 验收：普通用户登录后 5 页数据全为本人（A/B 双用户验证）；管理员接口不可越权调用（403）；踢自己会话生效、踢别人 404。

## DT-3 用户管理打磨

- **删除「新建用户」**（按钮 + `POST /api/admin/users` 接口下线；用户只能自助注册）。
- 行内操作：**编辑（仅改角色 admin/user，用户名/邮箱只读，绑定 Steam 账号只读展示）/ 重置密码（单条）/ 禁用·启用 / 踢会话 / 删除**；
  角色变更、禁用、删除二次确认 + 审计（`admin.user_edit` / `admin.user_disabled` 等）。
- **批量只保留「批量踢会话」**；其余（禁用/启用/删除/重置密码）不做批量。
- 编辑弹窗：显示该用户绑定的 Steam 账号（昵称 + SteamID，只读）——管理员不看其它个人信息（昵称/简介/邮箱只读亦可隐藏）。
- 验收：无新建入口/接口；编辑仅角色可改且审计；行内五个操作可用；批量仅踢会话；禁用用户会话立即失效（复用 BK）。

## DT-4 验证码体验（冷却隔离 + 倒计时 + 重置密码弹窗）

- 后端：验证码冷却**按场景分桶**——后台「重置密码发码」不占用前台「登录/注册发码」的冷却额度；
  返回 `retryAfterSec` 供前端倒计时。
- 前端：所有验证码按钮统一**倒计时 60s**（发送中/剩余秒数/可重发三态），不用报错提示代替。
- 重置密码弹窗（后台）：打开**不发码**；用户点「发送验证码」才发；验证失败**不关弹窗**（显示「还剩 N 次机会」）；
  过期显示「重新发送」（冷却结束可点）。
- 验收：后台发码后前台登录不被冷却拦截（分桶）；倒计时正确；失败不关弹窗；过期可重发；重开弹窗不自动发码。

## DT-5 前后台入口

- 前台：未登录顶栏显示「登录」按钮（点击跳 `/login`）；**登录后前台不显示「退出登录 / 修改密码」**。
- 后台（Console 全局顶栏，所有 section 共用）：右上「返回网站 ↗ + 用户徽标」；
  徽标点开**下拉菜单树**：个人资料 / 修改密码 / 返回网站 / 退出登录（普通用户同样可用）。
- 验收：未登录只见登录按钮；登录后前台无退出/改密；后台任何菜单页都有全局顶栏菜单树；退出后回到未登录态且心跳基线正确。
