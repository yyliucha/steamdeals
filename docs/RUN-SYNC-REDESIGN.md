## 2. 已确认的决策（2026-11-10 所有者，方案 A）

| # | 决策 |
|---|---|
| 1 | 顶部新增「任务健康条」：一行 chips（任务名 · 最近状态 · 耗时 · 下次运行），点击 chip 过滤该任务日志 |
| 2 | 「同步记录」表精简：列合并为 `时间 / 模式 / 状态 / 结果 / 耗时 / 备注`；默认只显示**最近 5 轮**，可展开看全部 20 轮 |
| 3 | 「日志面板」**固定高度 55vh 内部滚动**：筛选条 sticky 在面板头，日志行紧凑单行（时间·级别·事件·关键字段），点击行展开完整字段 |
| 4 | 默认最新在前；自动刷新开关放在日志面板头（不再单独占一行） |
| 5 | 移动端：任务健康条横向滚动，日志面板全宽、高度 50vh，其余堆叠 |

## 3. 设计

### 3.1 任务健康条（新增）

- 数据来源：`GET /api/admin/sync/status`（已有接口，无需新后端）；
- 每条 chip：`任务名` + 状态色点（最近成功→绿 / 最近失败→红 / 未跑过→灰）+ `耗时` + `下次 xx 分后`；
- 点击 chip = 把日志筛选设为该任务（`grep=任务名` 或前端按 `event` 包含任务名过滤）；
- 右侧「刷新」按钮同时刷新健康条与记录表；数据每 60 秒自动刷新（页面可见时）。

### 3.2 同步记录表（精简）

| 列 | 说明 |
|---|---|
| 时间 | `started_at` |
| 模式 | 现有 `syncModeLabel` 映射 |
| 状态 | 成功/运行中/失败/已停止（保留现有 tag） |
| 结果 | 把「请求数/总量/成功/跳过/失败」合并为友好文案：`成功 89 / 跳过 0 / 失败 0`（无数据时 `—`） |
| 耗时 | 现有 `syncDuration` |
| 备注 | 现有最后一行输出（tooltip 全文） |

- 默认显示最近 **5 轮**；「展开全部（20 轮）」按钮切换；
- 行点击不跳转；失败行保持红色左条。

### 3.3 日志面板（固定高度）

- 外层：`max-height: 55vh; overflow-y: auto`（内部滚动，不拉长页面）；
- 面板头 sticky：级别筛选（全部/INFO/WARN/ERROR 平铺 chips）+ 模块下拉 + 时间范围 + 搜索框 + 自动刷新开关 + 刷新按钮；
- 行：单行 flex——`时间 | 级别 tag | 事件 | 关键字段摘要（各字段 key=value 截断 1 行）`，点击展开完整 `logDetails`；
- 分页保留在面板底部（20/页）；无日志显示空态。

### 3.4 不变项

- 接口参数与返回不变（`/api/admin/logs`、`/api/admin/sync/runs`、`/api/admin/sync/status`）；
- 10 秒自动刷新逻辑保留（只换开关位置）；
- 不新增依赖。

## 4. 验收

1. 桌面 1440×900：打开「运行与同步」**不用滚动**即可看到任务健康条 + 记录表前 5 行 + 日志面板头；
2. 日志面板内部独立滚动，页面总高不再随日志条数增长；
3. 任务健康条显示每个任务最近状态/耗时/下次运行；点击 chip 后日志只显示该任务相关条目；
4. 同步记录默认 5 轮，点「展开全部」显示 20 轮；列已精简为 6 列；
5. 日志行点击展开完整字段，收起正常；级别/模块/时间/关键词筛选与自动刷新可用；
6. 移动端（≤760）：健康条横向滚动、日志面板全宽可滚动、无横向溢出；
7. `npm test` 全绿（`test/admin-console-ia.test.js` 增加本页静态断言：任务健康条/固定高度/5 轮折叠）、
   `npm run frontend:build`、`npm run scan`。
