## 1. 现状与问题（2026-11-18 线上 v2.24.3）

- 页面结构：标题 + 说明 + 「刷新」+ 黄色横幅「后台生成中（已处理 X/Y 组）」+ 表格（杉果名/SKU 数/候选/分数/方式/建议/操作）；
- **进度无意义**：横幅长期显示 `0/0 组`（`/api/admin/align` 202 响应的 `total` 在分组完成前为 0），
  用户看不出到底要算多少、还要多久；
- **空态误导**：生成中（202 无数据）时同时显示「暂无数据」+「没有待对齐的组」，两种语义混在一起；
- 视觉：统计信息缺失（有多少待审、多少自动、多少需人工）、没有筛选/搜索、批量操作只有表格内小链接，表格信息密度低。

## 2. 新布局（以 demo 为准）

| 区域 | 内容 |
|---|---|
| 头部 | 标题 + 说明；右侧状态徽标（**已生成 / 生成中 / 生成失败**）+「生成于 HH:mm」+「刷新」 |
| 统计卡（5） | 待对齐组 / 涉及 SKU / 自动匹配（≥0.94）/ 需人工（0.86–0.94）/ 本次自动继承条数 |
| 进度横幅 | **仅生成中显示**：进度条 + `已完成 X / 共 Y 组` + 「可先用旧结果」提示；Y 在分组后立即上报，不再出现 0/0 |
| 工具栏 | 搜索（杉果 SKU 名 / 候选游戏名）+ 筛选 chip（全部/高置信/需人工/无候选/已忽略）+ 批量确认/批量忽略 |
| 表格 | 勾选 · 杉果名（组）+ 英文名 · SKU 数 · 候选（名称 + 来源/AppID + 疑似本体提示）· 分数（色条：绿/黄/红）· 方式 · 建议（高置信/需人工/无候选/内容词）· 操作（确认/换候选/忽略）· **链接/明细（Steam ↗、杉果 ↗、明细）** |
| 明细面板 | 点「明细」展开该组全部候选（名称/AppID/分数/reasons/来源），**每个候选带 Steam 链接**；顶部带该组所有 SKU 的**杉果链接**（https://www.sonkwo.hk/sku/<skuId>），供人工判定 |
| 分页 | 共 N 组 · 第 x/y 页 |
| 空态 | 仅当**已完成且 0 组**时显示：「没有待对齐的组（新 SKU 会在杉果同步后进入队列）」 |

## 3. 数据/接口改动

- `GET /api/admin/align`：
  - 生成中：返回 `202 { generating: true, processed, total, cachedRows? }`，其中 `total` 在 `groupItems()` 完成后立即上报；
    **同时返回上一轮缓存的分页数据**（`stale: true`），前端可"先用旧结果"；
  - 已完成：返回 `{ groups, total, counts: { groups, skus, auto, manual, noCandidate, inherited }, generatedAt, cached }`；
- 统计口径：`auto` = 分数 ≥0.94；`manual` = 0.86–0.94；`noCandidate` = 无候选；
- **链接字段**：候选 `steam_appid` → `https://store.steampowered.com/app/<appid>/`；组内每个 `skuId` → `https://www.sonkwo.hk/sku/<skuId>`；
- **明细数据**：`groups[].candidates` 返回该组 top-N 候选（score/method/reasons/appid/name），供「明细」面板渲染；
- 前端：`AlignAdmin.vue` 按 demo 重排；生成中轮询 3s，完成后自动刷新；筛选/搜索前端先过滤（数据量小）。

| demo 状态 | 断言点 | 预期 |

| 头部「已生成」+「生成于 2026-11-18 14:20」 | 状态与时间 | 缓存命中显示已生成 + 生成时间；生成中显示「生成中」 |
